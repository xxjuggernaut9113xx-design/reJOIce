# CockHero recovered Unreal project

Open `CockHeroRecovered.uproject` with Unreal Engine 5.3.2. This is a separate, editable partial reconstruction, not the original source project or a finished full-game recreation.

Validation: the editor module builds successfully; all 111 imported progression rows and 39 player defaults match recovered values; eight rebuilt Blueprint classes compile. Seven `CockHero.Recovery` automation tests pass with zero failures or unexpected warnings. These cover 170 state traces, 146 session traces, 2,016 event-weight traces, 186 beat queues, native metric ordering and media-filter boundaries. The traces are static models of decoded source, not observations of the original executable running. Reports are in `Saved/reconstruction-validation.json` and `Saved/Automation/index.json`. The MSVC14.44 compatibility predicate is confined to this project's forced-include header; the engine installation is unchanged by that fix.

Recovered content: three difficulty profiles; 62 pattern slots; 31 event records; 60 named event entry points; 55 challenge, 20 level and 36 player-card rows; eight manager/save default definitions; selected decoded function bodies. The C++ rule library implements checked difficulty assignments, heat updates, inclusive chance comparison and native timing clamps. Newly created Blueprint classes expose these C++ parents and recovered evidence. Original Blueprint graph layouts are not recoverable from this cooked build.

`Content/Recovery` contains editable data assets and tables. `Content/NewSetup` contains rebuilt Blueprint shells, whose original event graphs are not yet restored. `RecoveryEvidence` preserves source data, decoded bytecode and native pseudocode. Soft asset references are preserved as original path strings: original images, sound and maps have not been imported or recreated. The workspace level is a development inspection scene, not the original game map.

Additional C++ reconstruction now exposes 39 recovered player fields, native session metrics, preference multipliers, combo classification, device-dependent timing selection, beat/voice pitch calculations, coin and meter updates, and selected metric ordering. `RecoveryEvidence/state-rule-traces.json` contains 170 independently evaluated bytecode cases. Out-of-range combo counts fall through to tier 5; meter additions remain unclamped. Device inputs are modeled; no hardware adapter is connected. Native lifetime maxima, challenge execution and persistence effects remain separate unfinished work.

Additional reconstruction includes beat rewards and meter modifier ordering, sequence completion, weighted event adjustment and selection, and a ticking beat timeline with rests, pause/resume and completion callbacks. Media filtering preserves native preference aliases, case-insensitive exclusions, multiple deck membership, duplicate tags and the five-deck fallback rotation. Filename tags use the native vocabulary and ordering. `ReadPackManifest` resolves local files without modifying the source pack. A separate Unreal media adapter exposes image loading and video opening; playback, audio and visual fidelity have not been validated in the GUI.

Remaining: startup and session state machine, complete event/card/resource interactions and eligibility, outcome/postgame logic, complete timing/audio/media integration, original presentation, progression execution, save compatibility and device adapters. No full-game completion is claimed. No AvtoHmver or original game/save files are modified.
